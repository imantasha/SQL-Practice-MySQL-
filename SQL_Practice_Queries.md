# SQL Practice Queries — E-Commerce Dataset

**Dataset:** `sql_practice_dataset.xlsx`
**Tables:** `customers` (600 rows) · `products` (217 rows) · `employees` (30 rows) · `orders` (5,200 rows) · `order_items` (13,156 rows)

## How to use this with SQL (not just Excel)
Excel alone can't run SQL. Load these sheets into a real database so your GitHub repo shows actual SQL, not just spreadsheet formulas:
- **Easiest:** Import each sheet as a table into **MySQL Workbench**, **PostgreSQL (pgAdmin)**, or **SQLite** (DB Browser for SQLite — no server install needed).
- **Or:** Use **Google BigQuery / Google Sheets + BigQuery connector**.
- **Or:** In Python, `pandas.read_excel()` each sheet, then `df.to_sql()` into a local SQLite file — this is the fastest path and works well for a GitHub project (I can build this loader script for you if you want).

### Suggested schema relationships
- `orders.customer_id` → `customers.customer_id`
- `orders.employee_id` → `employees.employee_id`
- `order_items.order_id` → `orders.order_id`
- `order_items.product_id` → `products.product_id`

## 1. Basic SELECT / WHERE / ORDER BY
1. Retrieve all columns from `customers`.
2. Get `first_name`, `last_name`, `city` for customers in the `"Corporate"` segment.
3. Find all orders with `order_status = 'Cancelled'`.
4. List products priced above 20000, sorted by `unit_price` descending.
5. Find customers who signed up after `'2023-01-01'`.
6. Get distinct `country` values from `customers`.
7. Find orders placed using `'UPI'` or `'Wallet'` (use `IN`).
8. Find products with `stock_quantity` between 0 and 20 (use `BETWEEN`).
9. Find customers whose email contains `'gmail'`... (there's none here — try `email LIKE '%1%'` instead, or search `product_name LIKE '%Laptop%'`).
10. Get the top 10 highest-value orders (`ORDER BY order_total DESC LIMIT 10`).

## 2. Aggregate Functions & GROUP BY / HAVING
11. Count total number of orders.
12. Find total revenue (`SUM(order_total)`) from all delivered orders.
13. Find average `unit_price` per `category` in `products`.
14. Count number of orders per `order_status`.
15. Find total quantity sold per `product_id` (from `order_items`).
16. Find number of customers per `country`.
17. Find categories where average unit price is above 5000 (use `HAVING`).
18. Find employees who have handled more than 150 orders (`GROUP BY employee_id HAVING COUNT(*) > 150`).
19. Find the minimum and maximum `order_total` per `payment_method`.
20. Find total revenue per month (`GROUP BY strftime('%Y-%m', order_date)` in SQLite, or `DATE_FORMAT` in MySQL).

## 3. JOINs
21. `INNER JOIN` `orders` with `customers` to show customer name next to each order.
22. `INNER JOIN` `order_items` with `products` to show product name, quantity, and line total.
23. Three-way join: `orders` + `customers` + `order_items` to show which customer bought what.
24. `LEFT JOIN` `employees` with `orders` to find employees with **zero** orders (if any).
25. `LEFT JOIN` `products` with `order_items` to find products that were **never ordered**.
26. Join `orders` + `employees` to show total revenue generated by each employee.
27. Join `customers` + `orders` + `order_items` + `products` to find total spend per customer per category.
28. Self-join idea: find pairs of customers from the same `city` (using `customers a JOIN customers b ON a.city = b.city AND a.customer_id <> b.customer_id`).

## 4. Subqueries
29. Find customers who have placed more orders than the average number of orders per customer.
30. Find products priced above the average `unit_price` of their own category (correlated subquery).
31. Find the customer(s) with the single highest total spend (subquery in `WHERE`).
32. Find orders whose `order_total` is greater than the average `order_total` of all orders.
33. Find employees whose total handled revenue is below the average across all employees.
34. Use `EXISTS` to find customers who have never placed an order (if any exist after filtering).

## 5. Window Functions
35. Rank customers by total spend using `RANK()` or `DENSE_RANK()`.
36. Use `ROW_NUMBER()` to find each customer's most recent order.
37. Calculate a running total of revenue over time using `SUM(order_total) OVER (ORDER BY order_date)`.
38. Use `LAG()` / `LEAD()` to compare each order's total to the customer's previous order.
39. Use `NTILE(4)` to split customers into spending quartiles.
40. Find each product's rank within its category by total quantity sold (`RANK() OVER (PARTITION BY category ORDER BY ...)`).
41. Calculate a 3-order moving average of `order_total` per customer using a window frame.

## 6. Date & String Functions
42. Extract year and month from `order_date` and count orders per period.
43. Calculate average number of days between `order_date` and `ship_date`.
44. Find orders placed on weekends vs weekdays.
45. Use `CONCAT`/`||` to build a `full_name` column from `first_name` and `last_name`.
46. Use `UPPER()`/`LOWER()` to standardize `city` names.
47. Find customers whose `email` domain is `example.com` (string parsing with `SUBSTRING`/`INSTR`).

## 7. CASE Statements & Conditional Logic
48. Create a new column that labels orders as `'High Value'` (>10000), `'Medium'` (2000–10000), or `'Low'` (<2000).
49. Categorize customers into age groups (`'18-25'`, `'26-40'`, `'41-60'`, `'60+'`) using `CASE`.
50. Flag orders as `'Delayed'` if `ship_date - order_date > 5` days.

## 8. Data Analysis / Business Questions (for your portfolio write-up)
51. Which product category generates the most revenue overall?
52. Which 10 products are the best sellers by quantity?
53. What is the month-over-month revenue trend for the last 2 years?
54. Which customer segment has the highest average order value?
55. What is the order cancellation/return rate by `ship_mode`?
56. Which region (via employees) is the top revenue generator?
57. What is the customer retention pattern — how many customers ordered in more than one calendar year?
58. What is the average discount given per category, and does higher discount correlate with higher quantity sold?
59. Identify the top 5% of customers by total spend (Pareto/"80-20" analysis) using `NTILE` or percentile logic.
60. Build a simple RFM-style summary: Recency (days since last order), Frequency (order count), Monetary (total spend) per customer.
